# Listing summary reports

In Master Listing Owner, choose **Paste listing report**, paste a dated report and choose **Preview report**. Review the matches, then choose **Apply matched listings**. `WTL-YYYYMM-NNNNN` means Rental; `WTS-YYYYMM-NNNNN` means Subsale Direct Listing. Date headings use DD/MM/YYYY. Repeated numbering, WhatsApp formatting, invisible formatting characters and `Name` without a colon are supported.

Confirmed entries update the existing master's owner name and phone, set seeding to Contacted and status to Listed, and create or restore its linked category row. Existing category rows receive the owner/contact and a readable report-information block in Notes containing the reference and report date. Original property, price, location, expiry, publication links and notes are preserved. The report date never becomes an expiry date. A repeated submission does not create another owner, category row or duplicate report update.

When no possible owner exists and the report fields/reference are valid, **Create missing owner and category row — details pending** is selected in the preview. Applying creates a master owner with Contacted + Listed, an unknown price and pending property type; the linked category row has Pending status and a reminder to complete missing details. Uncheck creation to keep the report entry pending. Existing matching names/phones, conflicting references and ambiguous matches require manual review. Use **Search existing owners** and **Confirm owner match** to resolve these. Permissions do not disambiguate otherwise identical properties, and only the assigned agent or Admin may update an existing owner. Automatic agent assignment stays paused.

## Property reports with advertisement links

Every category sheet and All Listings has **Paste property report**. Paste one property's report, starting with its property heading (for example `FOR SALE | Sample Gardens • RM500,000`), optional `REF: WTS-202610-00123`, owner/contact and numbered platform links. Headings/ref identify Rental or Subsale; other destinations can be selected in preview. Review the existing match or create a new row with Pending status. Duplicate/ambiguous properties require an explicit existing selection. References and exact normalized property names are checked across categories and the archive. Importing an archived match restores that same row.

Usable HTTP(S) links are saved as Published ads. Exact channel names and unambiguous platform aliases are proposed; choose a channel for unresolved links. Empty, N/A and Done entries are not advertisement links. The complete report, including price, owner/contact, skipped links and Done markers, is retained in Notes. Existing property names, schedules, statuses and notes are preserved. Repeated imports skip existing URLs. Failures roll back the property, reference, ads and audit together. If an own-property report was imported before its owner summary, the summary reuses the referenced category row and its ads.

Migration `0011_listing_report_creation.sql` permits unknown owner prices, adds the pending property type and creates `listing_report_references`. Existing rows are not rewritten. Tests: `npm run test:listing-reports` and `node --import tsx scripts/listing-report-ui-check.ts` against the synthetic integrated preview.

**Save pending changes** stores references and manual selections without applying them. Saved pending reports can be reopened after closing the modal or reloading; **Load older pending reports** reaches older pages. Completed reports do not hide pending work. A failed apply retains the current UI selections; if a listing changed, reopen the report to review current versions before retrying.

The creator and Admin can access a saved report. Reports contain owner/contact information and are stored in `owner_summary_reports`; they are not exposed through public endpoints. Reports are limited to 50,000 characters and 100 entries. Only reviewed selections are applied. A single transaction validates current permissions, owner versions, reference uniqueness and destination categories before changing owners, categories, report outcomes and audit history together. A failure rolls back the selected batch. Each semantic entry is recorded in owner history so retries and overlapping reports do not duplicate the operation.

## Release

Migration `0010_owner_summary_reports.sql` adds the saved-report table and creator/update index. It does not modify existing property data. Migration 0009 is included unchanged to reconcile the already-applied automatic-assignment pause; automatic assignment stays off. Run `npm run db:migrate` through the verified direct connection before deploying the API/UI; do not use `db:push`.
